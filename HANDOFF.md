## Where things stand

### Built and verified ✅

The Apliiq MCP server in `apliiq-mcp/`. Client/transport split per spec §3, three tools (`list_products`, `get_product`, `upload_artwork`), 28 tests passing with `fetch` stubbed, CI green, verified end-to-end with a real MCP handshake.

Signing tests pin the algorithm against digests generated by **OpenSSL, not by this codebase** — so they verify the implementation rather than agree with it. If you change `signRequest`, regenerate them with `openssl` by hand.

### Built but NOT verified against reality ⚠️

**Nothing the MCP server returns should be trusted yet.** The build environment's egress policy blocked every `*.apliiq.com` host, so three things went in as assumptions transcribed from the spec:

1. The HMAC signature construction — `signRequest()` in `apliiq-mcp/src/apliiq-client.ts`
2. The catalog endpoint paths — `ENDPOINTS`, same file
3. `upload_artwork`'s request body field names — `apliiq-mcp/src/tools.ts`

`npm run smoke` is built to tell these apart, because from a failed tool call a bad secret, a bad signature and a bad URL path look identical. Tracked as issue #1.

### Deliberately not built

`create_order` and `get_order_status`. Spec §5 says resolve the field-level shapes first; that never happened. Issue #2. Note that `create_order` would be the first **mutating** tool — it spends real money and produces real garments, so it needs a dry-run or confirmation path designed in, not bolted on.

## Ground rules worth not relearning

- `APLIIQ_SHARED_SECRET` never enters git. `.env` is gitignored and CI fails if one becomes tracked. If it ever *is* committed, rotating it in the Apliiq dashboard is the fix — removing the commit is not enough.
- Secret scanning / push protection are **unavailable** on this repo: it is private, and those are free only on public repos (otherwise they need paid GitHub Advanced Security). The CI guard is the compensating control.
- Under stdio, **stdout belongs to the MCP protocol**. A single `console.log` anywhere in the server process corrupts the stream. Diagnostics go to stderr.
- Don't build against unconfirmed API shapes. Spec §5 sets this rule for the order endpoints; it applies generally.
